# Spec: `src/utils/i18n.js`

## Propósito
Sistema de internacionalización con traducciones embebidas para español e inglés. Proporciona funciones de traducción, cambio de idioma, y actualización del DOM.

## Dependencias

### state
| Propiedad | Acceso (R/W) | Contexto |
|-----------|-------------|----------|
| `localStorage` | read/write | almacenar `weatherhist_language` |

### DOM
| Elemento | Tipo de acceso | Contexto |
|----------|---------------|----------|
| `[data-i18n]` | querySelectorAll / textContent | applyTranslations |
| `[data-i18n-placeholder]` | querySelectorAll / setAttribute | applyTranslations |
| `[data-i18n-title]` | querySelectorAll / setAttribute | applyTranslations |

## API Pública

### `export const translations: Object`

**Descripción:** Objeto con traducciones para `es` y `en`, organizado por secciones: config, theme, overlay, search, map, nav, topPanel, pollen, minimap, weatherCodes, weather, aqiLevel, aqi, pollenLevels, days, months.

### `export function setLanguage(lang: string): void`

**Descripción:** Cambia el idioma activo si existe en `translations`, persiste en localStorage y aplica traducciones al DOM.

**Parámetros:** `lang: string` — `'es'` o `'en'`

**Mutates state:** localStorage

### `export function getLanguage(): string`

**Descripción:** Retorna el idioma activo actual.

**Retorno:** `'es'` | `'en'`

### `export function t(key: string, fallback?: string): string`

**Descripción:** Traduce una clave anidada (e.g. `"config.language"`). Retorna el valor traducido, el fallback si se provee, o la propia clave si no encuentra nada.

### `export function getLocale(): string`

**Descripción:** Retorna el locale para formato de fechas según el idioma activo.

**Retorno:** `'es-ES'` | `'en-US'`

### `export function applyTranslations(): void`

**Descripción:** Recorre el DOM y actualiza `textContent`, `placeholder`, y `title` de elementos con atributos `data-i18n`, `data-i18n-placeholder`, `data-i18n-title`.

## Comportamiento

1. `currentLanguage` se inicializa desde localStorage o default `'es'`
2. `setLanguage` solo cambia si `translations[lang]` existe
3. `t(key)` recorre keys separadas por `.` para acceso anidado
4. Los weatherCodes usean `t('weatherCodes.' + code)` con fallback a `weatherCodes.unknown`

## Casos borde

| Entrada | Comportamiento esperado |
|---------|------------------------|
| `t('clave.inexistente')` | Retorna `'clave.inexistente'` |
| `t('clave.inexistente', 'fallback')` | Retorna `'fallback'` |
| `setLanguage('fr')` | No cambia (no existe en translations) |
| Código WMO no cubierto | `t('weatherCodes.' + code)` retorna `'weatherCodes.unknown'` → fallback a `t('weatherCodes.unknown')` |

## Escenarios de test

1. **Traducción directa:** `t('config.language')` retorna el string esperado según idioma
2. **Clave anidada:** `t('days.short.0')` retorna el primer día
3. **Fallback:** clave inexistente con fallback retorna el fallback
4. **Sin fallback:** clave inexistente sin fallback retorna la propia clave
5. **getLanguage:** retorna el idioma actual
6. **setLanguage:** cambia el idioma y persiste en localStorage
7. **getLocale:** `es` → `'es-ES'`, `en` → `'en-US'`
8. **applyTranslations:** actualiza elementos del DOM con data-i18n
